# `app/` — the Expo client

Loads when a session touches `app/`. The root `CLAUDE.md` holds what is not app-only: CI,
migrations, deploy, the working agreement and graphify. **Nothing checks this file**, so it
carries commands, never counts. Editing it fires `app.yml`.

`app/` is the fourth workspace (`@tienda/app`). **Read [`docs/CONVENTIONS.md`](../docs/CONVENTIONS.md)
before writing a file here** — it governs how every file is written, and
`bash docs/checks/conventions-gate.sh` enforces it (and prints the counts it measured).

## Measure, don't remember

```
find app/src/app -name '*.tsx' | wc -l    # routes + the two _layout.tsx (a layout is not a screen)
ls app/src/api | wc -l                    # data-layer modules
npm --prefix app test                     # the test tally — the RUNNER's, never a grep of the files
```

## Rules

- **Tests** live in `app/test/` as `.ts` and reach no component (`R2`). A unit test is in scope
  where it pins a value a customer sees or the ledger stores — never rendering, navigation or
  layout (ADR-035 §2.11).
- **`app/src/ui/` primitives** (`R14`–`R16`): a component moves there only once a second module
  draws it; one component per file, named after the file, never `export default`; a difference
  between copies becomes a prop, and a difference nobody decided becomes a decision reported
  to the owner. The filled button and the veil are `BotonLleno` and `Velo` since `8f`; the
  chosen pill is still un-extracted — why is in `docs/CONVENTIONS.md`; re-measure with its
  predicate before extracting.
- **A module in `app/src/api/` is a claim about the applied schema**, which is why `db.yml` fires
  on it. Its wire behaviour is proven only by the matching `docs/checks/*-contract.sh` against a
  real PostgREST — never by a typecheck or a Vitest fixture.
- **A new route needs the typed-route declarations regenerated** (Metro is the only generator),
  or the local typecheck rejects it while CI goes green.
- **`app/ios/` is generated by `expo prebuild` and gitignored** — no workflow compiles it.
- **Ship an over-the-air update only with `docs/runbooks/ship-an-update.sh`, never a bare
  `eas update`.** The runtime is a fingerprint, and `eas update` publishes to a runtime no
  build has without an error. A new native dependency means a new build before any update.
- **A shopkeeper never sees an internal state or an edge case.** What a screen renders is the
  owner's call; ask before changing it.

## Traps a session would otherwise re-discover

Each was measured against a real PostgREST or device.

- **Refusals differ by verb.** An RLS INSERT refusal is **403 `42501`**; an UPDATE refusal is
  **200 with `[]`** — `.select().single()` turns it into PGRST116. A custom SQLSTATE (e.g.
  `TD003`) and `restrict_violation` (`23001`) arrive as **HTTP 400**, not 403 or 409.
- **An embed on a fenced table is a 200 with `[]`** — the document renders with no lines. Test
  the privileged actor too, or the check is vacuous.
- **A wire value is not its label.** `@/api/documents` renders a waste cause through
  `reasonLabel`; sending the label back is a 400 `22P02` no typecheck can see. Carry the value
  beside the word (`reasonValue`, `causeValue`).
- **Postgres enums sort by declaration**, not alphabetically — a picker and a report agree only
  if both use that order.
- **Nothing records a document's line order** (no ordinal; identical `created_at`), so lines are
  ordered by product name through a nested embed. A parent order needs the column in the embed's
  select, or it is `42703`.
- **`normalize_name` folds case and whitespace, not accents** — `checkProvider` is stricter on
  purpose. `provider_protect_generic` does not stop deactivating the generic row; `canRetire`
  does.
- **`record_waste` dedupes nothing**, and `unit_price_gross_per_base` is required, so an
  unpriced product is written off at an explicit zero (`UNPRICED_WASTE`).
- **`void_transaction`'s window runs from `recorded_at` on an offline write** — the clock starts
  when a document lands. The client draws only the clock-free half of the fence.
- **Offline is the normal path.** `QueryProvider.tsx` persists a named set of query keys to the
  device (`@/api/persist`). A persisted query needs `gcTime` raised or it is silently dropped;
  the persist buster is a shape version, never the signed-in user; `forgetCache` is called from
  `signOut` alone, because clearing on `session === null` wipes the catalog on a failed refresh.
- **A queued write has no row in Postgres**, so `Lo último` draws the outbox too
  (`@/offline/unsent`). Dropping a queued write is not a void; the delete's own `changes` count
  is the evidence. No screen reads the queue directly (`auth-errors.test.ts`).
- **A tab screen keeps stale mount state** — `useState(() => …)` never sees a store change made
  from another screen.
- **`grep -q` under `pipefail` fails on big files** (SIGPIPE) — use `grep -c` in any check.
